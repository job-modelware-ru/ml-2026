# Отчёт за 12.10–18.10

**Проект:** «Распознавание окружающих звуков»  
**Команда:** 8

## 1. Цель работы за отчётный период

Разработать серверную часть приложения на FastAPI: загружать сохранённую модель
один раз при запуске сервера, предоставить методы проверки состояния и получения
списка классов, принимать аудиофайл для распознавания, возвращать три наиболее
вероятных класса в формате JSON и обрабатывать некорректные запросы.

## 2. Что было сделано

### 2.1. FastAPI-приложение

- Создан отдельный модуль серверной части `api.py`.
- Сохранённая модель загружается во время запуска приложения и затем повторно
  используется всеми запросами без переобучения и повторной десериализации.
- Реализован метод `GET /health`, возвращающий состояние сервера, признак
  загрузки модели и количество поддерживаемых классов.
- Реализован метод `GET /classes`, возвращающий полный список из 50 классов
  ESC-50 в порядке, зафиксированном в модельном артефакте.
- Реализован метод `POST /predict`, принимающий аудиофайл как
  `multipart/form-data` и возвращающий имя файла, три наиболее вероятных класса,
  их уверенности и время обработки моделью.
- Синхронное извлечение признаков и прогнозирование выполняются в рабочем потоке,
  чтобы не блокировать цикл обработки асинхронных HTTP-запросов.
- Добавлена команда `uv run serve-api` для локального запуска сервера Uvicorn.
- Схемы успешных ответов и ошибок описаны моделями Pydantic и отображаются в
  автоматически создаваемой документации FastAPI по адресу `/docs`.

### 2.2. Проверка и ограничение загружаемых файлов

- Разрешены контейнеры WAV, FLAC и OGG и распространённые для них MIME-типы.
- Максимальный размер одного загружаемого файла ограничен 10 МиБ.
- Файл читается порциями по 64 КиБ, поэтому превышение ограничения обнаруживается
  без загрузки всего тела в память приложения.
- Запросы с неподдерживаемым расширением или несовместимым MIME-типом получают
  ответ `415 Unsupported Media Type`.
- Слишком большие файлы получают ответ `413 Content Too Large`, а пустые и
  повреждённые аудиофайлы — `422 Unprocessable Content` с понятным описанием.
- Для совместимости с существующим модулем прогнозирования загруженная запись
  сохраняется во временный файл с исходным расширением. Файл удаляется после
  успешного прогнозирования и после ошибок.

### 2.3. Зависимости и документация

- Добавлены FastAPI, Uvicorn и `python-multipart`, необходимый для приёма файлов.
- Для тестирования HTTP-методов добавлен актуальный тестовый клиент `httpx2`.
- Файл блокировки `uv.lock` обновлён для воспроизводимой установки зависимостей.
- README дополнен инструкцией запуска API, таблицей методов, примерами запросов
  `curl`, описанием ограничений и кодов ошибок.

### 2.4. Автоматические и ручные проверки

- Добавлены тесты методов `/health`, `/classes` и `/predict` с изолированным
  тестовым классификатором.
- Проверены структура успешного ответа, возврат ровно трёх результатов и удаление
  временного файла.
- Добавлены тесты неподдерживаемого расширения, несовместимого MIME-типа,
  превышения размера, пустого файла и ошибки декодирования.
- Общее количество автоматических тестов увеличилось с 12 до 19; все 19 тестов
  успешно проходят.
- Статический анализ Ruff и проверка форматирования проходят без замечаний.
- Сервер дополнительно запущен через Uvicorn и проверен реальными HTTP-запросами
  ко всем трём методам.

## 3. Полученные результаты

### 3.1. Проверка методов API

| Метод | Проверка | Результат |
|---|---|---|
| `GET /health` | модель загружена, доступно 50 классов | `200 OK` |
| `GET /classes` | возвращён список классов ESC-50 | `200 OK`, 50 классов |
| `POST /predict` | загружена настоящая WAV-запись ESC-50 | `200 OK`, top-3 в JSON |
| `POST /predict` | неподдерживаемый тип файла | `415 Unsupported Media Type` |
| `POST /predict` | размер больше 10 МиБ | `413 Content Too Large` |
| `POST /predict` | пустой или повреждённый контейнер | `422 Unprocessable Content` |

Для сквозной проверки использована запись дождя `1-17367-A-10.wav`. Запрос к
работающему серверу вернул следующие результаты:

| Место | Класс | Уверенность |
|---:|---|---:|
| 1 | `rain` | 0,8350 |
| 2 | `helicopter` | 0,1126 |
| 3 | `door_wood_creaks` | 0,0152 |

Таким образом, серверный метод использует тот же сохранённый конвейер, что и
локальная команда прогнозирования, а правильный класс остался на первом месте.

### 3.2. Время обработки через API

При первом запросе после запуска процесса обработка контрольной записи заняла
около 633 мс из-за однократной инициализации библиотек обработки аудио. Следующие
пять запросов заняли в среднем 19,05 мс каждый. Это согласуется с измерениями
модуля прогнозирования на предыдущем этапе. Время передачи файла по сети и
обработка multipart-формы в поле `processing_ms` не входят: оно измеряет чтение
временного аудиофайла, подготовку сигнала, извлечение признаков и классификацию.
