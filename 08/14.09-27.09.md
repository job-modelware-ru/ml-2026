# Отчёт за 14.09–27.09

**Проект:** «Распознавание окружающих звуков»  
**Команда:** 8

## 1. Цель работы за отчётный период

В отчёте объединены результаты работы за две недели: подготовка единого
конвейера обработки аудио и извлечения признаков, а также обучение и сравнение
первых классических моделей классификации.

## 2. Что было сделано

### 2.1. Подготовка аудио

- Определён единый формат входа модели: mono, 22 050 Гц, 5 секунд, 110 250
  отсчётов.
- Реализовано преобразование многоканального аудио в один канал усреднением
  каналов.
- Добавлено приведение записей к частоте дискретизации 22 050 Гц.
- Реализовано дополнение коротких записей тишиной и обрезка длинных записей до
  пяти секунд.
- Добавлена пиковая нормализация громкости до амплитуды 0,95. Полностью тихие
  записи обрабатываются без деления на ноль.
- Обработка вынесена в повторно используемый модуль
  `src/sound_recognition/audio.py`.

### 2.2. Извлечение признаков

- Для каждой записи вычисляются MFCC, первые и вторые производные MFCC, chroma,
  спектральный центроид, спектральная ширина, spectral rolloff, частота
  пересечения нуля и RMS-энергия.
- Для каждого покадрового признака сохраняются среднее значение и стандартное
  отклонение. В результате одна запись преобразуется в вектор из 154 чисел.
- Извлечение признаков вынесено в модуль
  `src/sound_recognition/features.py` и использует те же параметры обработки,
  что и будущий модуль прогнозирования.
- Реализована проверка метаданных и наличия всех аудиофайлов ESC-50.
- Добавлен локальный кэш признаков. Он проверяется по списку файлов, параметрам
  обработки и версии схемы признаков, поэтому устаревший кэш автоматически
  пересоздаётся.
- Подготовлен и полностью выполнен notebook
  `notebooks/02_audio_features_and_baselines.ipynb` с проверкой признаков на
  классах `dog`, `keyboard_typing`, `rain`, `sea_waves` и `siren`.

### 2.3. Baseline и первые модели

- В качестве нижней границы качества добавлен классификатор, всегда выбирающий
  наиболее частый класс.
- Обучены логистическая регрессия, метод опорных векторов с RBF-ядром и случайный
  лес.
- Для всех моделей использовано одинаковое разделение ESC-50: fold 1–4 (1 600
  записей) для обучения и fold 5 (400 записей) только для проверки.
- Все случайные компоненты зафиксированы значением `random_state = 42`.
- Для каждой модели измерены accuracy, macro F1, время обучения и среднее время
  получения предсказания.
- Для лучшей по macro F1 модели построена нормализованная матрица ошибок и
  сохранена таблица наиболее частых ошибок классификации.
- Добавлена команда `uv run train-baselines`, полностью воспроизводящая
  извлечение признаков, обучение, оценку и сохранение результатов.

### 2.4. Проверка качества кода

- Добавлены автоматические тесты преобразования stereo в mono, изменения частоты
  дискретизации, дополнения до заданной длительности, нормализации, обработки
  тишины и извлечения вектора признаков.
- Все 3 теста успешно проходят.
- Код проверен Ruff: ошибок форматирования и статического анализа нет.
- Notebook выполнен целиком через `nbconvert` без ошибок.

## 3. Полученные результаты

### 3.1. Параметры конвейера признаков

| Параметр | Значение |
|---|---:|
| Частота дискретизации | 22 050 Гц |
| Количество каналов | 1 (mono) |
| Длительность | 5 секунд |
| Отсчётов в записи | 110 250 |
| Пиковая амплитуда после нормализации | 0,95 |
| MFCC | 20 коэффициентов |
| Размер итогового вектора | 154 признака |
| Обработано записей ESC-50 | 2 000 |

Конвейер возвращает вектор одинакового размера для каждой записи и не создаёт
значений `NaN` или `inf`. Для повторных экспериментов признаки сохраняются в
локальном кэше размером около 1,1 МБ, который не добавляется в Git.

### 3.2. Сравнение моделей

| Модель | Accuracy | Macro F1 | Обучение, с | Предсказание, мс/запись |
|---|---:|---:|---:|---:|
| RBF SVM | 0,5525 | **0,5410** | 0,15 | 0,14 |
| Случайный лес | **0,5575** | 0,5301 | 0,66 | 0,06 |
| Логистическая регрессия | 0,4950 | 0,4846 | 0,11 | < 0,01 |
| Наиболее частый класс | 0,0200 | 0,0008 | < 0,01 | < 0,01 |

Нижняя граница accuracy равна 2%, что ожидаемо для 50 сбалансированных классов.
Все три обучаемые модели значительно превосходят эту границу. Случайный лес
показал наибольшую accuracy, но RBF SVM получил лучший macro F1 и поэтому выбран
как наиболее перспективный подход для следующего этапа. Macro F1 используется
как основной показатель, поскольку он одинаково учитывает каждый класс.

В матрице ошибок заметны трудные пары акустически похожих или неоднозначных
классов. Например, встречаются ошибки `laughing` → `crying_baby`, `wind` →
`helicopter`, `clapping` → `footsteps`, `crackling_fire` → `water_drops`.
На следующем этапе эти ошибки будут использованы для выбора улучшенных признаков
и параметров модели.
