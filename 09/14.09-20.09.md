# Отчет за первую неделю разработки детектора пилообразных колебаний на основе МО

## Описание проекта

Цель проекта — разработать автоматический детектор срывов пилообразных колебаний в сигналах диагностик плазмы.

Для обработки экспериментальных разрядов необходимо автоматически определять моменты срывов. Детектор на основе методов машинного обучения должен устойчиво работать на различных видах пил, то есть сохранять качество при изменении амплитуды, периода, уровня шума и формы сигнала.

На данном этапе в проекте уже имеется алгоритмический детектор. Он включает предварительную обработку SXR-сигнала, оценку периода с помощью автокорреляции и быстрого преобразования Фурье, а также непрерывное вейвлет-преобразование. Алгоритмический детектор находит характерные быстрые фронты, однако его качество зависит от выбранных порогов и особенностей конкретного разряда. На сложных пилах встречаются ложные срабатывания и пропуски срывов.

В исходном варианте решение принимается исходя из анализа энергетического профиля вейвлетного преобразоания (иначе говоря, формы одного SXR-сигнала). При этом файл разряда SHT содержит несколько SXR-каналов и набор других диагностических сигналов, которые характеризуют процессы в плазме в тот же момент времени. Поэтому ML-детектор изначально рассматривается как многоканальный: кандидаты формируются по всем доступным SXR-каналам, а для их классификации используются признаки из SXR и сопутствующих диагностик.

Основная идея ML-ветки заключается в двухступенчатом детектировании:

1. Физически интерпретируемый алгоритм формирует кандидаты на срыв по доступным SXR-каналам
2. Выбранная ML-модель классифицирует каждый кандидат как реальный срыв или ложное срабатывание, используя признаки из нескольких сигналов разряда

Такой подход выбран из-за ограниченного количества размеченных данных. Обучать модель на каждой точке временного ряда на первом этапе нецелесообразно: большая часть отсчетов относится к фону, а подтвержденных событий сравнительно мало. Классификация заранее найденных кандидатов уменьшает размер обучающей выборки и сохраняет связь результата с физической формой сигналов.

Параллельно рассматривается отдельная real-time ветка. Ее задача — детектировать срывы по мере поступления данных, не дожидаясь завершения разряда. Для нее необходимо отдельно проанализировать доступность каналов в реальном времени, допустимую задержку, причинную обработку сигналов и модели, которые могут работать на скользящем окне или поддерживать внутреннее состояние.

## Цели первой недели

На первую неделю были поставлены следующие задачи:

- Проанализировать существующий обычный детектор и определить, какие его части можно использовать для формирования кандидатов
- Упорядочить набор экспериментальных разрядов по сложности: разнести файлы по папкам `easy`, `medium`, `hard` и `notSaw`
- Сформулировать архитектуру многоканального feature-based ML-детектора
- Определить набор локальных признаков, описывающих форму срыва в SXR-сигналах
- Изучить состав других сигналов, содержащихся в SHT-файлах, и определить, какие признаки можно извлекать из них около кандидата
- Определить способ приведения каналов с разными временными сетками к общей шкале и обработки отсутствующих каналов
- Проанализировать real-time ветку: предполагаемый поток данных, ограничения по задержке и причинности, а также возможные модели
- Начать реализацию первого программного прототипа классификатора кандидатов

## Анализ обычного детектора

Обычный детектор используется как базовый алгоритм и как генератор кандидатов для ML-модели. В его работе можно выделить следующие этапы:

1. Загрузка SHT-разряда и выбранных SXR-каналов
2. Выделение плазменного интервала по току плазмы
3. Очистка и нормализация сигнала
4. Оценка характерного периода пилообразных колебаний
5. Построение непрерывного вейвлет-преобразования
6. Расчет энергетического профиля и поиск его локальных максимумов
7. Подавление слишком близких пиков

Для ML-ветки из обычного детектора в первую очередь нужны:

- Подготовка и нормализация SXR-сигнала
- Оценка глобального или локального периода
- Поиск быстрых фронтов
- Оценка выраженности кандидата
- Временная привязка события
- Подавление дублей

Обычный детектор не требуется заменять полностью. Его задача в новой схеме — обеспечить высокую полноту кандидатов. ML-модель должна затем отфильтровать ложные срабатывания с учетом информации из нескольких каналов.

## Архитектура многоканального ML-детектора

### Формирование кандидатов

Кандидаты предлагается формировать по всем доступным SXR-каналам: `SXR 15 мкм`, `SXR 27 мкм`, `SXR 50 mkm`, `SXR 80 mkm` и `SXR 127 мкм`.

Для каждого канала запускается обычный генератор кандидатов. Близкие по времени предложения объединяются в одно событие. При этом не следует требовать обязательного совпадения во всех каналах: часть каналов может отсутствовать, иметь низкое отношение сигнал/шум или хуже видеть конкретный срыв.

Для объединенного кандидата сохраняется информация о том:

- Какие SXR-каналы его предложили
- Каким методом он был найден
- Насколько различаются оценки кандидата по каналам
- Каков временной разброс между предложениями

### Работа с каналами SHT

На первом этапе необходимо загружать и изучать все доступные каналы каждого SHT-файла. Для построения устойчивой модели затем фиксируется упорядоченный профиль каналов. Если отдельного сигнала в разряде нет, схема признаков не должна меняться: для него сохраняются признак отсутствия и пустые значения.

Помимо SXR в текущем наборе рассматриваются следующие группы диагностик:

- Ток плазмы
- Сигналы D-alpha
- Внешние и быстрые МГД-зонды
- Положение плазмы
- Напряжения электродов, инжектора и магнитных петель
- Радиометр
- Диамагнитный сигнал

Разные каналы могут иметь собственные шаги дискретизации и временные сетки. Для "офлайн-модели" их необходимо привести к временной шкале опорного SXR-сигнала.

### Признаки SXR

Для опорного SXR-сигнала сохраняется набор локальных признаков первой версии:

- Общая физическая оценка кандидата
- Амплитудная выраженность скачка
- Выраженность производной
- Величина падения или инвертированного роста
- Среднее, стандартное отклонение, MAD и полный размах локального окна
- Минимум, максимум и разброс производной
- Асимметрия и эксцесс
- Изменение среднего и разброса после события относительно участка до события

Для каждого дополнительного SXR-канала:

- Наличие канала
- Факт формирования кандидата этим каналом
- Используемый метод формирования кандидата
- Нормированное изменение уровня до и после события
- Знак и величину скачка
- Отношение локальной энергии после события к энергии до события
- Максимальную локальную производную
- Положение наиболее сильного изменения относительно кандидата
- Локальный шум и отношение скачка к шуму

### Признаки других диагностик

Для каждого сопутствующего сигнала признаки вычисляются в локальном окне вокруг SXR-кандидата. На первом этапе предлагается использовать небольшой общий набор:

- Доля валидных отсчетов в окне
- Нормированное изменение медианного уровня до и после кандидата
- Знак и величина скачка
- Изменение локальной энергии
- Максимальная абсолютная производная
- Временное смещение наиболее сильного изменения относительно SXR-кандидата

Дополнительно признаки агрегируются по физическим группам каналов. Например, для группы МГД-зондов можно вычислять максимальный скачок и максимальную производную среди доступных зондов, а для D-alpha — медианное изменение уровня и долю каналов с валидными данными.

На первой неделе задача состоит не в доказательстве полезности каждого сигнала, а в построении общей схемы, которая позволит сравнить их вклад после обучения модели.

## Идея построения обучения

Обучение предлагается организовать следующим образом:

1. Сформировать список разрядов по категориям `easy`, `medium`, `hard` и `notSaw`
2. Разделить данные на обучение и проверку по целым разрядам, а не по отдельным кандидатам
3. Получить первичную разметку событий 
4. Сформировать объединенные кандидаты по всем доступным SXR-каналам
5. Присвоить кандидатам классы по временному расстоянию до размеченных событий
6. Извлечь многоканальные признаки из SXR и остальных диагностик
7. Обучить базовый табличный классификатор
8. Выбрать порог вероятности на validation-наборе

В качестве первой модели подходят CatBoost, XGBoost или `HistGradientBoostingClassifier`. Они позволяют быстро проверить полезность многоканальных признаков и работают с небольшим табличным датасетом.

Основные метрики первого этапа:

- Полнота генератора кандидатов относительно разметки
- Precision, recall и F1 классификатора
- Число ложных срабатываний на один разряд
- Качество отдельно на `easy`, `medium`, `hard` и `notSaw`
- Качество при отсутствии части каналов

## Дополнительная real-time ветка

Real-time ветка решает ту же задачу, но работает с последовательно поступающими отсчетами. Она не может использовать будущие значения сигнала, симметричные окна вокруг события или интерполяцию, которой нужны точки справа от текущего момента.

Перед реализацией необходимо определить какие каналы доступны во время разряда, а какие появляются только после его завершения, частоту поступления каждого канала и способ причинного выравнивания временных сеток, допустимую задержку обнаружения, длину рабочего окна и частоту запуска модели, способ обработки временно пропавших каналов, формат состояния, которое переносится между последовательными окнами.

Возможные модели для real-time режима:

- TCN или компактная 1D CNN 
- GRU или LSTM
- Transformer
  
CatBoost или XGBoost по идее тоже можно использовать в real-time режиме. Однако они не обрабатывают сырой поток самостоятельно: перед моделью все равно необходимы буферизация, синхронизация каналов и вычисление признаков только по прошлым и текущим отсчетам.
