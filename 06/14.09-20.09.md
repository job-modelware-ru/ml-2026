# Отчёт о проделанной работе за неделю (14.09–20.09.2026)

## Тема проекта

**«Технологический трекер Hacker News» — веб-сервис аналитики и прогнозирования популярности технологий на основе постов и комментариев Hacker News**

Сервис собирает статьи и комментарии с Hacker News, строит семантические связи между упоминаемыми технологиями, анализирует тональность обсуждений и (в перспективе) прогнозирует рост интереса к технологиям на основе исторических паттернов. Результаты предоставляются пользователю через веб-интерфейс.

## Проделанная работа

### 1. Выбор и обоснование темы
- Рассмотрено несколько вариантов курсового проекта (рекомендательные системы, классификация текста, sentiment-анализ отзывов и др.).
- Остановились на теме с данными Hacker News: большой открытый API, живые данные, возможность совместить несколько ML-задач (NER/классификация технологий, эмбеддинги, sentiment-анализ, предиктивная модель) в одном продукте.
- Определена новизна: помимо описательной аналитики (что уже упоминалось), реализуется прогнозная часть — предсказание роста интереса к технологиям на основе динамики упоминаний и семантической близости к уже "взлетевшим" технологиям.

### 2. Анализ предметной области и аналогов
- Изучен Hacker News API (Firebase API): структура items (story/comment/job), доступные поля, лимиты по частоте запросов.
- Просмотрены существующие паблик-дашборды и инструменты аналитики HN (hnrankings, hckrnews и др.) — определены пробелы: почти нигде нет прогнозной составляющей и семантической карты технологий.
- Изучены базовые подходы к задачам:
  - извлечение упоминаний технологий из текста (rule-based vs NER);
  - обучение эмбеддингов на предметно-специфичном корпусе (Word2Vec/FastText);
  - лексиконные и ML-подходы к sentiment-анализу коротких неформальных текстов.

### 3. Проектирование архитектуры
Определена предварительная схема сервиса:

- **Data layer** — сбор данных через HN API, хранение в реляционной БД (SQLAlchemy, SQLite для разработки / PostgreSQL для прод).
- **ML/analytics layer** — построение эмбеддингов технологий, классификация статей по технологиям, расчёт метрик вовлечённости и тональности.
- **Backend (API)** — FastAPI-сервис, отдающий агрегированные данные и результаты ML-моделей по запросу фронтенда.
- **Frontend** — интерактивный дашборд (карта связей технологий, динамика упоминаний, sentiment-тренды).

### 4. Настройка окружения и репозитория
- Создан git-репозиторий проекта, определена структура директорий (данные, скрипты сбора, аналитика, backend, frontend).
- Настроено виртуальное окружение, зафиксирован базовый список зависимостей (requests/HTTP-клиент, SQLAlchemy, FastAPI, gensim/spaCy — предварительно).
- Составлен `requirements.txt` с базовым набором пакетов.

### 5. Предварительная работа с данными
- Написан прототип скрипта для скачивания диапазона items с HN API с поддержкой многопоточной загрузки и сохранения в сжатом формате (jsonl.gz).
- Спроектирована предварительная схема БД: таблицы для историй (Story), комментариев (Comment), технологий (Tech) и связи many-to-many между Story и Tech.
- Проведён пробный запуск сбора данных на небольшом диапазоне ID для проверки работоспособности пайплайна и оценки объёма/качества данных.

## Проблемы и риски
- HN API не имеет прямого поиска/фильтрации по темам — весь отбор нужно делать постфактум по тексту, что увеличивает объём скачиваемых данных.
- Неформальный стиль текста (сленг, сокращения, код в комментариях) может затруднить как построение эмбеддингов, так и sentiment-анализ — потребуется более тщательная предобработка текста.
- Нужно заранее продумать способ инкрементального обновления данных, чтобы не перекачивать весь корпус заново.
