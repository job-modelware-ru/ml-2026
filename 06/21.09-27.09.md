# Отчёт о проделанной работе за неделю (21.09–27.09.2026)

## Тема проекта

**«Технологический трекер Hacker News»** — веб-сервис аналитики и прогнозирования популярности технологий на основе постов и комментариев Hacker News.

## Кратко

На этой неделе основное внимание было уделено данным. Пайплайн сбора доведён до рабочего состояния и проверен на большем объёме. Загрузка в БД теперь переживает повторные запуски без дублей, написана предобработка текста. Составлена первая версия словаря технологий, по нему размечены истории. Проведён первый (базовый) эксперимент с обучением Word2Vec на заголовках.

## Проделанная работа

### 1. Сбор данных с Hacker News
- Прототип загрузчика превращён в CLI-скрипт `scripts.retrieve`. Диапазон ID задаётся аргументами `-s/-e`, при их отсутствии берётся актуальный `maxitem` из API. Число потоков, сжатие и частота вывода прогресса настраиваются.
- Загрузка сделана потоковой: одновременно выполняется не больше `workers` запросов, результаты сразу пишутся в `jsonl.gz`. Весь диапазон в памяти не держится.
- По завершении выводится статистика: сколько ID просмотрено, сколько items сохранено, число ошибок, скорость (items/s) и размер файла.
- Добавлен скрипт `scripts.combine` для склейки нескольких выгрузок в один файл с удалением дубликатов (по хешу строки или по канонизированному JSON). Он нужен, потому что корпус скачивается частями, и диапазоны могут пересекаться.
- Добавлен скрипт `scripts.create_samples` для небольших демонстрационных наборов (reservoir sampling, фильтр по типу items). Они используются для быстрой отладки без полной БД.
- Цепочка «загрузка → склейка → импорт в БД» прогнана на нескольких диапазонах ID по 10 000 items.

### 2. Загрузка данных в БД
- Финализирована схема: `Story`, `Comment`, `Tech` и связующая таблица `story_tech` (SQLAlchemy 2.0, типизированные поля `Mapped`).
- Реализованы класс `HNHandler` и CLI `db.scripts.ingest`: чтение `jsonl/jsonl.gz`, разбор items по типам, пакетная вставка с настраиваемым размером батча.
- Вставка сделана через upsert (`ON CONFLICT DO UPDATE` для SQLite/PostgreSQL, `ON DUPLICATE KEY UPDATE` для MySQL). Повторный импорт тех же items не создаёт дублей, а обновляет изменившиеся поля (score, число комментариев, список ответов). Это закрывает риск инкрементального обновления, отмеченный на прошлой неделе.
- Истории без заголовка отбрасываются, HTML-сущности в тексте комментариев декодируются при загрузке.

### 3. Предобработка текста
- `utils/clean_text.py`: декодирование HTML-сущностей, удаление тегов, замена markdown-ссылок на их текст, удаление URL, нормализация пробелов.
- `utils/lemmatize.py`: токенизация регулярными выражениями (слова с дефисами и апострофами, числа), приведение к нижнему регистру, замена чисел на токен `<NUM>`, лемматизация через spaCy (`en_core_web_sm`). Компоненты `parser` и `ner` отключены, а каждый уникальный токен лемматизируется один раз (с кешем). Это заметно ускорило обработку.
- Выяснилось, что spaCy искажает часть названий технологий (например, `windows → window`, `ios → io`). Добавлен список слов-исключений, которые не лемматизируются (`windows`, `ios`, `macos`, `aws`, `kubernetes`, `postgres`, …). Список можно дополнять из файла.
- CLI `analytics.embeddings.scripts.lemmatize_file` (TXT → TXT, построчно) с флагами `--no-lemmatize`, `--keep-punct`, `--preserve-words`.
- Скрипты выгрузки из БД: `db.scripts.export_titles` (только заголовки) и `db.scripts.export_context` (заголовок и текст комментариев к истории одной строкой).

### 4. Словарь технологий и первичная разметка историй
- Выбран rule-based подход вместо NER. Размеченных данных для обучения NER нет, а список интересующих технологий конечный и известен заранее.
- Словарь (`analytics/embeddings/patterns.py`) устроен как отображение «каноническое имя → список регулярных выражений». Кроме самого названия, паттерны включают характерные инструменты экосистемы (например, `pip`, `poetry`, `pytest` → python; `cargo`, `crates.io` → rust).
- Для неоднозначных названий (`go`, `rust`, `swift`, `c`, `r`) используются контекстные паттерны (`golang`, `goroutine`, `go mod`, `swiftui`, `C++20`, `ggplot2` и т. п.), а не голое слово.
- Первая версия словаря покрывает языки программирования, операционные системы и контейнеризацию. Остальные группы (СУБД, LLM и ML-модели) в работе.
- Скрипт `analytics.embeddings.scripts.classify_tech` проходит по историям, ищет совпадения в заголовках и заполняет связь `story_tech`. Недостающие записи `Tech` создаются автоматически.
- Скрипт `db.scripts.trim` удаляет истории, в которых не нашлось ни одной технологии. Режим `--dry-run` позволяет сначала оценить объём удаления.

### 5. Первые эксперименты с эмбеддингами
- Токенизированный корпус сохраняется в `jsonl.gz` (одна строка — список токенов), поэтому при обучении он читается потоково.
- Обучен базовый Word2Vec (gensim, skip-gram, размерность 300, окно 5, `min_count=2`, 5 эпох) только на заголовках.
- Результат пока неудовлетворительный: заголовки короткие, многие технологии встречаются редко, и списки ближайших соседей получаются шумными. Поэтому решено расширить корпус текстом комментариев, для этого и написан `export_context`. Обучение на расширенном корпусе и сравнение с базовой моделью запланированы на следующую неделю.

### 6. Окружение и черновик API
- Обновлён `requirements.txt`: spaCy 3.7 с моделью `en_core_web_sm`, gensim 4.3, pandas, scikit-learn. Версии numpy и scipy зафиксированы (1.26 и 1.13), так как gensim 4.3 несовместим с numpy 2.x.
- Для бэкенда подтверждён FastAPI + Pydantic. Составлен черновик эндпоинтов:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/techs` | список технологий с категориями и числом упоминаний |
| GET | `/api/techs/{name}/timeline` | динамика упоминаний по периодам |
| GET | `/api/techs/{name}/similar` | ближайшие технологии по эмбеддингам |
| GET | `/api/stories?tech=...` | истории, в которых упоминается технология |

Эндпоинты для тональности и прогноза будут добавлены, когда появятся соответствующие модели.

## Проблемы и риски
- Словарь даёт ложные срабатывания на общеупотребительных словах: `stack` (haskell), `arch` и `mint` (linux), `otp` (erlang, но чаще «одноразовый пароль»), `composer` (php). Нужно вручную проверить разметку на выборке и уточнить паттерны.
- Загрузчик учитывает, но не перезапрашивает items, на которых произошла сетевая ошибка. Из-за этого в данных возможны пропуски, нужен retry с паузой.
- В `export_context` сейчас попадают только комментарии первого уровня (прямые ответы на историю), вложенные ветки обсуждений не учитываются.
- Комментарии содержат фрагменты кода, цитаты и ссылки. После добавления их в корпус шум вырастет, возможно, понадобится дополнительная фильтрация.
- Классификация пока работает только по заголовкам. Истории, где технология упоминается лишь в комментариях, не размечаются.
