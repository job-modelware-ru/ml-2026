# Отчёт о проделанной работе

## Что сделано

- **Продумана и закодирована стратегия генерации датасета (точек коллокации) для PINN.**  
  В `pinn_project/src/sampling.py` реализованы: подбор размера расчётной области (L, T) исходя из динамики волнового пакета, расчёт минимального объёма точек коллокации из требований разрешения (длина волны де Бройля по x, ширина пакета по t), сама генерация точек со сгущением у разрывов потенциала и у t=0, а также заготовка Latin Hypercube-выборки по пространству параметров для будущей параметризованной модели. Физика (потенциалы, волновой пакет, аналитические D) вынесена в `pinn_project/src/physics.py`.

- **Обнаружено, что (L=10, T=5) из карточки проекта не согласуются с динамикой пакета при дефолтных параметрах (x₀=-3, k₀=2.0, b=0.5, барьер d=1).**  
  При такой энергии (ε=k₀²=4.0, режим «над барьером») центр прошедшей части к t=5 находится на x≈+16.5, отражённой — на x≈-17.0, то есть пакет покидает область ещё при t≈2 и дальше нефизично отражается от жёсткого условия Ψ(±L,t)=0. Это напрямую портит интеграл Dₚᵢₙₙ по формуле (11), который как раз предполагает большое T уже после разъезда частей. Два варианта исправления: либо сократить T до физически оправданных ≈1.6-2.5, либо, если T=5 нужен ради более плавной анимации, увеличить L до ≈20-25. Полезное следствие: после того как пакет выходит из зоны барьера/ямы, динамика там снова свободная (V=0) — для «долгой» демо-анимации её можно достроить аналитической формулой свободного движения (уже проверенной в Тесте 1), не растягивая под неё расчётную область и обучение PINN.

- **Пересчитан рекомендованный объём датасета для одной фиксированной конфигурации.**  
  Для L≈8, T≈2.5 (с запасом поверх рекомендации выше) минимальное число точек «сеточного» разрешения — 31×120≈3 720 для domain. С учётом того, что случайная/Sobol-выборка покрывает пространство менее эффективно, чем регулярная сетка, предлагается брать с запасом ×1.5-2: ~6 000-8 000 domain-точек (из них ~30% — в узких полосах вокруг x=0 и x=d по всем t, ~25% — в первые 20% времени), ~300-400 boundary-точек (условие Ψ=0 самое простое, большой плотности не требует) и ~250-300 initial-точек, из которых 60% сконцентрированы в пределах ±4b от x₀ (где пакет реально не равен нулю). Для сравнения, в карточке проекта стояло 10 000/1 000/2 000 — т.е. boundary и initial там, похоже, избыточны, а вот под изначально слишком большую (L,T) и domain=10000 было явно недостаточно.

- **Подготовлен отдельный валидационный набор (9 эталонных точек), не пересекающийся с обучающими точками коллокации.**  
  3 точки в режиме туннелирования, 3 — над барьером, 3 — резонансные энергии ямы (2k₂a=πn, где Dₐₙₐₗᵢᵗ=1 точно). Будет использоваться только для подсчёта ошибки модели.

- **Оценён риск единой расчётной области для будущей параметризованной модели**  
  Для диапазона энергий ε∈[0.1, 5.0] разброс групповой скорости пакета — около 7×. Если подбирать общие (L,T) под самый медленный пакет (T≈10.3), то самому быстрому пакету за это время потребуется L≈48.5 — то есть расчётная область окажется почти пустой для большинства параметров. Зафиксировано как открытый вопрос: либо сузить диапазон ε на первой версии параметризованной модели, либо обезразмерить время под скорость конкретного пакета.
